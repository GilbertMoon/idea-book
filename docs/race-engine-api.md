# Race engine rendering and integration contract

`new RaceEngine({groups, settings, obstacleSettings, isShuffled})` exports both named and default class. `start()` returns true once, false after departure. `step(dt=1/120)` accumulates fixed 1/120 second ticks (incoming frame time capped at .25 seconds). `getRanking()` returns copies with groupName/memberName, seconds arrivalTime, shared competition rank (1,1,3), or null rank and dnfReason `time-limit`. No collision count or ID breaks arrival ties; tolerance is one microsecond.

Logical size: width1200 height820. `lanes` provides stage,left,right,top,bottom; stage centers 160,600,1040. Ball radius12. `finishY=700` crosses when the leading ball edge reaches the line. READY advances animationTime only; RUNNING advances elapsed seconds. Empty departure finishes safely.

`balls`: id/groupId/groupName/memberName/imageUrl, x/y/vx/vy, radius, stage (1..3), route, arrivalTime (seconds or null), collisionCount, returnCount, returnFromStage2, returnFromStage3, returnCooldown (seconds), dnf/dnfReason. transport.start is the actual intake point for rendering the full dynamic throat. stage remains the source stage during a return corridor; changes on continuous re-entry. First member supplies the image; team name supplies the label. Starting order can be shuffled once; neither names nor IDs select physics/routing.

`obstacles`, `gates`: x/y center, length, thickness, angle (radians), angularVelocity (radians/second), stage; type segment/paddle/oscillating/gate. Endpoints are center ± (cos(angle),sin(angle))*length/2. Oscillating x is updated and baseX retained. Custom old-board obstacle arrays or `{fixed:[],rotating:[],oscillating:[]}` are transformed into stage1; old PhysicsEngine is retained separately.

`routes`: `{id,points:[{x,y}],width:40,mechanical:true}`. Render as captive belt rails with directional markings. Conveyor and top connect stages; return2 and return3 are distinct side corridors. Bypass2 and bypass3 are physical motorized branch corridors, selected by the same count/cooldown rules for every ball. Bypass3 travels outside the right lane at x1170, clear of the entire rotating gate sweep. Lane walls have branch openings at transport mouths (not solid walls across these mouths); the belt confines the center inside its route corridor. Return entry from the actual impact position to the first route point is a continuation inside the gate mouth. Render the full mouth region as open and connected to the visible belt. Captive belt balls use a uniform 230px/sec motor and cannot intersect unrelated stage obstacles; no ball is teleported. The model follows a polyline with a bounded move per fixed tick, stopping momentarily at corners.

Protected bypass intakes are at stage2 y420 (through x690) and stage3 y155 (through x1170), above/below the full gate swept circles even at hard gate length145. Exhaustive fixed-tick clearance tests sample both routes from five starting x positions across each lane and all three difficulties against all current gate/obstacle segments. The first stage3 slope was removed to keep its entire intake throat clear. Conveyor and return3 release at (600,700); three ascent paddles occupy y650,580,510 so the top connector and bypass are unobstructed. Additional descent rotors occupy (90,640) and (970,400), length60. Gate lengths easy100/normal125/hard145 change contact area uniformly.

Stage2 uses a visible uniform air-lift field (-400px/sec², capped ascent240px/sec before contacts), plus alternating rotating physical paddles. Paddle collision uses closest point on the moving segment and relative normal velocity with true angular surface velocity. Paddles can raise or lower balls; contact timing changes progress. Stage1/3 gravity450px/sec², descent cap300; all collision velocity components bounded350. Fixed slope pairs cover the starting lane horizontally, with alternating downhill exits.

Gate return requires an actual incoming collision impulse, leftward outgoing vx<-35 and left-facing contact normal. Return limit defaults2, protection defaults1 second starting at corridor re-entry, race deadline defaults90 seconds. Exhausted/protected balls engage the visible right-side bypass before reaching a blade; obstacles remain solid. Ball/ball collisions are disabled, consistently with the old engine, so overlapping teams never wait for each other.

`events` resets at each `step` and retains all substep events during that call. Entries `{type:'collision'|'paddle'|'return'|'arrival',ballId,stage?,fromStage?,toStage?}`; return includes source/destination. Consume after each call, throttle sound in UI. `lastGateContact` on a ball records actual contact normal and elapsed time for live inspection.

Limitations: belts are ideal captive motors (kinematic rail contact), not simulated rotating rollers; lane sidewalls are clamped boundaries outside branch transport. User-created overlapping obstacles can create unrecoverable traps, which honestly become DNF at the configured deadline. No team-specific rescue or artificial completion is used.
