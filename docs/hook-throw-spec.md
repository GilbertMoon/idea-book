# IDEA-BOOK — 추격자 낚아채기(Hook & Throw) 기능 개발

## 1. 역할 및 목표

당신은 로컬 Codex 개발 에이전트입니다.

**Repository:** https://github.com/GilbertMoon/idea-book

**목표:** 기존 3단계 물리 기반 순위 정하기 게임에 플레이어 간 자동 추격 공격 기능을 추가합니다.

추격 중인 공이 앞선 공과 일정 거리 이내로 근접하면 낚싯대를 사용해 상대를 낚아채고, 뒤쪽으로 던져 순위가 역전될 수 있도록 구현하세요.

이번 작업은 단순 애니메이션이 아니라 **실제 레이스 경로상 위치가 변화하는 물리 기반 공격 시스템**을 구현하는 것입니다.

### 반드시 유지할 기존 기능

- React 19 + Vite 8
- Canvas 2D 자체 물리 엔진
- 3단계 레이싱 구조
- 1단계 하강, 2단계 상승, 3단계 최종 하강
- 컨베이어 및 회전 패들
- 2단계 → 1단계 복귀문
- 3단계 → 2단계 복귀문
- 팀 등록 및 사진 표시
- IndexedDB 기반 설정 저장
- Slack 결과 전송
- 기존 결과 순위 판정
- Playwright 및 단위 테스트

기존 기능을 불필요하게 수정하거나 제거하지 마세요.

# STEP 1. 기능 개념

## 1.1 추격 공격 시나리오

```text
① 정상 레이싱

    [2위 공]  →  →  →  [1위 공]

② 공격 거리 진입

    [2위 공]  →  [1위 공]

③ 낚싯대 자동 발사

    [2위 공] ──────── 🎣 [1위 공]

④ 앞선 공 낚아채기

    [2위 공] ←── [1위 공]

⑤ 뒤쪽으로 던지기

    [기존 1위 공] ← 뒤로 밀림

⑥ 추격자는 정상 진행

    [추격자] → 정상 진행

⑦ 물리 시뮬레이션에 따라 순위 역전 가능
```

### 핵심 규칙

- 공격은 자동 발동합니다.
- 사용자가 별도의 공격 버튼을 누르지 않습니다.
- 같은 경로에서 뒤따르는 공만 공격할 수 있습니다.
- 앞선 공이 뒤따르는 공을 공격할 수 없습니다.
- 공격자는 자신의 진행 방향을 유지합니다.
- 피격자는 실제 물리 상태에 역방향 운동량을 전달받습니다.
- 공격 성공이 반드시 순위 역전을 보장하지는 않습니다.
- 최종 순위는 결승선 통과 시각으로만 결정합니다.

# STEP 2. 추격 관계 판정

이번 개발에서 가장 중요한 로직입니다.

## 2.1 화면 거리만으로 공격하지 않기

기존 레이스는 다음 경로로 구성됩니다.

```text
Stage 1 : 하강
Conveyor : 오른쪽 이동
Stage 2 : 상승
Top Conveyor : 오른쪽 이동
Stage 3 : 하강
Finish : 결승선
```

화면에서 두 공이 가까워 보여도 반드시 같은 경로에서 앞뒤로 달리는 것은 아닙니다.

따라서 두 가지 조건을 함께 확인해야 합니다.

1. 동일한 진행 경로에 있는지
2. 해당 경로의 진행 방향 기준 누가 앞인지

### 진행 방향

| 구간 | 앞선 공의 기준 |
|---|---|
| 1단계 | y가 더 큰 공 |
| 2단계 | y가 더 작은 공 |
| 3단계 | y가 더 큰 공 |
| 수평 컨베이어 | 이동 방향 기준 더 앞쪽의 공 |
| 복귀·우회 통로 | 해당 통로의 실제 진행 거리 기준 |

초기 버전에서는 물리적으로 안전한 1·2·3단계의 일반 레이스 경로에서만 공격을 허용합니다.

컨베이어·복귀·우회 통로에서는 공격을 비활성화합니다. 추후 별도 확장이 가능하도록 구조를 설계하세요.

## 2.2 추격 판정 조건

다음 조건을 모두 만족해야 공격할 수 있습니다.

- 두 공 모두 RUNNING 상태
- 두 공 모두 결승선 미도착
- 두 공 모두 DNF 아님
- 두 공이 동일한 stage에 위치
- 두 공 모두 transport 상태가 아님
- 실제 진행 방향 기준 공격자가 뒤에 있음
- 두 공 사이의 실제 유클리드 거리가 공격 범위 이내
- 공격자 쿨다운 종료
- 공격자 사용 횟수 남음
- 피격 대상 보호시간 종료
- 현재 공격 애니메이션에 참여 중이지 않음
- 장애물·벽 등으로 인해 낚싯줄이 통과할 수 없는 상태가 아님

마지막 조건은 원형 공과 선분 장애물 간의 선분 교차 또는 적절한 선형 가시성 판정으로 구현하세요.

공격은 특정 팀 이름, ID, 등록 순서, 현재 순위 숫자에 따라 차별하지 않습니다.

## 2.3 추격 공격 거리

기본값은 공 지름의 3배입니다.

현재 공 반지름이 12라면:

```javascript
attackRange = 72
```

단, 거리 판정은 원의 중심 간 거리로 정의하고 관리자 UI에도 해당 기준을 일관되게 적용하세요.

공이 실제로 뒤따르는 상태인지 확인하기 위해 경로상 전후 거리 차이가 일정한 양수 이상이어야 합니다.

### 권장 함수

```javascript
getForwardDirection(ball)
getForwardGap(attacker, target)
getDistanceBetweenBalls(a, b)
hasHookLineOfSight(attacker, target)
canAttack(attacker, target)
findAttackTarget(attacker, balls)
```

동일한 stage라도 복귀 후 재진입한 공이 있으므로 과거 최고 진행도나 최초 출발 순서로 앞뒤 관계를 판단하지 마세요.

**현재 실제 위치를 기준으로 판단해야 합니다.**

# STEP 3. 공격 대상 선정

공격 가능한 대상이 여러 개일 수 있습니다.

예:

```text
진행 방향 →

3위 공 ── 2위 공 ── 1위 공
```

3위 공이 2위와 1위 모두 공격 범위에 있더라도 가장 가까운 앞선 공 하나만 선택합니다.

### 우선순위

1. 공격 가능한 앞선 공 검색
2. 진행 경로상 간격이 가장 작은 공 선택
3. 동일한 간격인 경우 실제 중심 간 거리 비교
4. 완전히 동일한 경우 결정적인 내부 정렬 기준 사용

내부 정렬 기준은 공격 이벤트의 중복 실행을 방지하기 위한 것이며, 경기 순위를 결정하는 기준으로 사용하지 마세요.

공격 판정은 고정 물리 스텝에서만 수행하여 화면 FPS에 영향을 받지 않도록 하세요.

# STEP 4. 낚싯대 공격 상태 머신

공격 상태를 분리하여 관리하세요.

```text
IDLE
  ↓ 공격 조건 충족
CASTING
  ↓ 낚싯대 발사
HOOKED
  ↓ 상대 포획
THROWING
  ↓ 뒤로 던지기
COOLDOWN
  ↓ 쿨다운 완료
IDLE
```

## 4.1 CASTING

- 공격자에서 목표 공 방향으로 낚싯대 발사
- 낚싯줄 또는 갈고리 렌더링
- 공격 대상 ID 고정
- 발사 시간 기록

기본 애니메이션 시간: 0.2초

## 4.2 HOOKED

- 목표 공에 갈고리가 걸리는 연출
- 목표 공 주변 강조 효과
- 낚싯줄 길이가 짧아지는 애니메이션

기본 애니메이션 시간: 0.15초

## 4.3 THROWING

목표 공에 진행 방향의 반대쪽으로 충격량을 부여합니다.

```text
Stage 1 : 위쪽으로 던짐
Stage 2 : 아래쪽으로 던짐
Stage 3 : 위쪽으로 던짐
```

피격자의 속도와 위치는 기존 물리 엔진에 의해 계속 갱신되어야 합니다.

공을 임의 좌표로 순간이동시키지 마세요.

### 중요

피격 대상은 장애물·벽과 계속 충돌해야 하며, 공격 때문에 기존 복귀문이나 컨베이어 규칙이 깨지면 안 됩니다.

단순히 `rank` 값을 바꾸는 방식은 절대 사용하지 마세요.

## 4.4 COOLDOWN

공격 종료 후 재사용까지 일정 시간 대기합니다.

기본 쿨다운: 8초

피격자는 별도 보호시간을 받습니다.

기본 보호시간: 2초

# STEP 5. 실제 물리 충격 처리

## 5.1 공의 이동 방향에 따른 역방향 충격

기존 RaceEngine은 다음 속도 값을 사용합니다.

```javascript
ball.vx
ball.vy
```

여기에 기존 stage의 진행 방향을 반영하여 충격을 가하세요.

개념 예시:

```javascript
const direction = getForwardDirection(target)

target.vx -= direction.x * impulse
target.vy -= direction.y * impulse
```

`impulse`는 기본 충격량이며 관리자 설정값으로 변경할 수 있도록 설계합니다.

현재 엔진의 속도 제한 및 충돌 규칙과 일관되게 처리하세요.

### 반드시 지킬 사항

- 충격은 한 번만 적용
- 물리 스텝마다 중복 충격 금지
- 속도 상한 유지
- 벽 관통 방지
- 장애물 통과 방지
- 피격 공을 즉시 결승선이나 이전 단계로 강제 이동시키지 않음

낚싯줄 애니메이션과 실제 충격은 분리하여 관리하되, 두 동작의 타이밍은 일치시킵니다.

## 5.2 공격 직후 역전

공격 성공 즉시 화면상의 순위 숫자를 바꾸지 마세요.

공격으로 목표 공이 뒤로 밀리고, 실제 이동 과정에서 추격자가 앞서게 되는 결과를 만들어야 합니다.

즉:

**공격 성공 ≠ 순위 역전 확정**

공격 이후 실제 추월이 일어났는지 별도 이벤트 또는 통계로 계산할 수 있지만, 경기의 최종 순위는 결승선에서만 확정합니다.

## 6.2 공격 횟수 처리

공격자별로 다음 정보를 관리하세요.

```javascript
{
  attackCount: 0,
  successfulAttacks: 0,
  hitCount: 0,
  attackCooldown: 0,
  hitProtection: 0,
  attackState: 'IDLE'
}
```

실제 코드에서는 필요에 따라 공격 상태 객체를 분리하세요.

### 보호 기능

- 피격 직후 2초 보호
- 동일 공이 동시에 여러 공격을 받지 않음
- 공격자가 피격 중이면 새로운 공격 불가
- 결승선 통과 후 공격 불가
- 복귀 통로 이동 중 공격 불가
- 공격 중 게임이 종료되면 진행 중인 공격 취소

공격 쿨다운 및 보호시간은 벽시계가 아닌 시뮬레이션 시간 기준으로 처리하세요.

# STEP 8. Canvas 낚싯대 애니메이션

기존 RaceRenderer.js를 확장합니다.

## 8.1 연출

공격 발생 시:

1. 공격자 주변 낚싯대 표시
2. 대상 방향으로 낚싯줄 발사
3. 목표 공에 갈고리 연결
4. 낚싯줄 당김
5. 대상이 뒤로 튕겨 나감
6. 공격 성공 이펙트 표시

낚싯줄은 직선 또는 곡선으로 표현할 수 있습니다.

Canvas 2D 기능만 사용하세요.

별도 이미지·애니메이션 라이브러리 도입은 필요하지 않습니다.

## 8.2 화면에서 구분

- 공격자: 발사 순간 강조
- 피격자: 짧은 충격 이펙트
- 낚싯줄: 기존 공 색상과 구분
- 보호 상태: 작은 보호 링 표시
- 쿨다운: 필요할 경우 간단한 표시

공과 조원 사진의 가독성을 해치지 않도록 구성하세요.

## 8.3 성능

- 매 프레임 React 상태 업데이트 금지
- Canvas 애니메이션은 기존 requestAnimationFrame 사용
- 물리 상태와 렌더링 분리
- 화면 크기에 따른 공격 판정 변화 금지
- 다수 팀에서 객체 생성 및 불필요한 연산 최소화

# STEP 10. 공격 성공·실패 처리

공격 조건을 만족한 순간부터 실제 충격 적용 시점까지 시간이 존재합니다.

그 사이 대상이 다음 상황이 될 수 있습니다.

- 다른 단계로 이동
- 컨베이어 진입
- 복귀 통로 진입
- 결승선 도착
- DNF 처리
- 다른 공격에 피격

이러한 경우 공격을 안전하게 취소하세요.

### 실패 정책

- 대상이 사라지거나 유효하지 않으면 공격 취소
- 공격 실패 이벤트 기록
- 실패 시 충격량 적용 금지
- 쿨다운 및 공격 횟수 소모 정책을 명확히 정의

권장 정책:

**실제 포획에 성공한 공격만 사용 횟수를 소모합니다.**

발사했지만 대상이 이탈한 경우에는 짧은 실패 쿨다운 1초를 적용합니다.

동일 물리 스텝에서 다수 공격이 발생할 때는 대상 점유 상태를 원자적으로 처리하여 중복 포획을 방지하세요.

공정성을 위해 팀 등록 순서나 배열 순회 순서가 공격 우선권에 영향을 주지 않도록 동시 판정 규칙을 설계하세요.

추월 횟수를 정확하게 측정하기 어렵다면 임의로 추정하지 말고 우선 공격·피격 횟수만 제공합니다.

- 공격 성공 횟수 추가
- 피격 횟수 추가
- 기존 Webhook 설정과 전송 로직 유지
- 경기당 자동 전송 1회 정책 유지

실제 Slack Webhook을 테스트에 사용하지 말고 Mock으로 검증하세요.

# STEP 12. 물리·게임 공정성 검증

### 반드시 확인할 항목

1. 공격 ON/OFF 모두 정상 진행
2. 뒤에 있는 공만 공격 가능
3. 공격 거리 밖에서는 발동하지 않음
4. 서로 다른 단계의 공을 공격하지 않음
5. 컨베이어와 복귀 통로에서 공격하지 않음
6. 피격 공에 실제 역방향 속도 변화 발생
7. 공격으로 공이 벽을 관통하지 않음
8. 공격 후 기존 장애물 충돌 정상
9. 공격 후 복귀문 동작 정상
10. 공격 후 정상적인 결승선 판정
11. 최대 공격 횟수 준수
12. 보호시간 준수
13. 공격 이벤트 중복 방지
14. 공격 애니메이션 완료 및 정리
15. 공격 OFF 시 기존 경기 동작 보존

### 추가 중요 테스트

- 같은 위치에 겹쳐 있는 공
- 공 1개만 등록한 경기
- 공 2개 경기
- 공 10개 경기
- 공 30개 경기
- 여러 공이 동시에 공격 범위에 진입
- 여러 공격자가 동일한 공을 목표로 선택
- 발사 직후 대상이 결승선을 통과
- 공격 중 대상이 복귀 통로에 진입
- 공격 직후 출발하거나 종료되는 경계 상태
- 60Hz와 120Hz 렌더링 간 결과 일관성
- IndexedDB 복구 및 이전 설정 호환성

### 안정성

공격 기능 때문에 경기 완료 시간이 지나치게 길어지지 않도록 검증하세요.

기존 90초 제한시간 및 DNF 정책을 유지합니다.

특정 팀을 강제로 완주시키거나 순위를 조작하지 마세요.

# STEP 13. 구현 모듈 권장 구조

기존 구조를 유지하되 다음 정도로 역할을 분리하는 것을 추천합니다.

```text
src/
 ├── physics/
 │    ├── RaceEngine.js
 │    ├── ChaseAttackSystem.js      ← 신규
 │    ├── RaceProgress.js           ← 필요 시 신규
 │    └── PhysicsEngine.js
 │
 ├── game/
 │    ├── Game.jsx
 │    ├── RaceRenderer.js
 │    ├── HookRenderer.js           ← 필요 시 신규
 │    └── Result.jsx
 │
 ├── config/
 │    └── defaults.js
 │
 ├── admin/
 │    └── Admin.jsx
 │
 ├── sounds/
 └── state/
```

### 모듈 책임

**ChaseAttackSystem**
- 공격 가능 여부 판단
- 대상 선택
- 공격 상태 머신
- 쿨다운 및 보호시간
- 공격 충격 적용
- 공격 이벤트 생성

**RaceProgress**
- 구간별 진행 방향
- 경로상 앞뒤 관계
- 물리적 거리 계산
- 연결부 및 복귀 구간 판정

**HookRenderer**
- 낚싯대
- 낚싯줄
- 갈고리
- 포획·투척 이펙트

공격 판정과 상태 머신이 React 컴포넌트에 직접 뒤섞이지 않도록 하세요.

RaceEngine은 공격 시스템을 고정 물리 스텝에서 호출하도록 연동합니다.
