# 순위 정하기 게임 · 3단계 물리 레이스

React 19 / Vite 8 / Canvas 2D / 자체 JavaScript 물리 엔진 / IndexedDB / Web Audio API. 별도 서버·DB·외부 물리 라이브러리를 사용하지 않습니다.

## 실행

```powershell
cd C:\dev\solar-work-lab\idea-book
npm install
npm run dev -- --host 127.0.0.1 --port 5188
```

http://127.0.0.1:5188/ 에 접속합니다. 브라우저 저장 데이터는 주소(origin)별로 분리됩니다. localhost와 127.0.0.1, 다른 포트를 섞으면 같은 팀 데이터가 보이지 않으므로 주소를 일정하게 사용하세요.

## 관리자 사용

1. 조 이름을 추가합니다. 목록의 이름 필드는 수정 후 포커스를 옮기면 반영됩니다.
2. ▼로 조를 펼쳐 조원 이름과 로컬 사진을 등록합니다. 첫 사진을 팀 공에 표시하며 사진 없이도 실행할 수 있습니다. 사진은 10MB 이하, 실제로 디코딩할 수 있는 이미지여야 합니다.
3. 사용자 장애물 추가/삭제, 시작 위치 셔플, 난이도, 두 복귀문의 활성화, 복귀 한도와 보호시간, 제한시간을 설정합니다. 기본 경기장에는 항상 엇갈린 경사판·회전·이동 장애물이 있습니다.
4. Slack을 사용한다면 URL을 입력합니다. '이 브라우저에 저장'을 선택한 경우에만 저장합니다. 저장된 URL은 비밀번호 입력창으로 마스킹됩니다. Webhook 삭제로 제거합니다.
5. '경기 준비'를 누르면 공이 출발대에 고정되고 장치만 움직입니다. '출발'을 누르면 동시에 시작합니다.
6. 모든 팀이 도착하거나 제한시간이 되면 결과를 표시합니다. '다시 경기하기'는 팀·사진·설정을 유지하고 READY로 돌아갑니다. '관리자 화면' 및 브라우저 뒤로 이동은 현재 경기만 취소합니다.
7. 팀 삭제/전체 초기화는 확인 후 수행하며 사진도 정리합니다. 설정과 현재 경기 초기화는 팀 삭제와 별개입니다.

## 물리·순위 규칙

- 1단계 하강 → 하단 벨트 → 2단계 패들 상승 → 상단 벨트 → 3단계 하강 → 결승선.
- 논리 경기장 1200×820, 고정 1/120초 물리 스텝. Canvas 크기와 DPR은 물리 좌표를 바꾸지 않습니다.
- 2단계는 회전 패들과 모든 공에 동일한 보조 상승 기류를 사용합니다. 공별 속도 지정이나 확률 기반 복귀는 없습니다.
- 두 회전문의 실제 충돌 반사 방향으로 복귀 여부를 판정합니다. 2→1과 3→2는 별도 벨트이며 순간이동하지 않습니다. 복귀 제한/보호시간 대상은 날개를 통과하지 않고 별도 우회 벨트를 이용합니다.
- 벨트는 일정한 모터가 공을 가이드 레일에 구속하는 이상적인 기계식 모델입니다. 회전 롤러 자체를 시뮬레이션하지 않습니다. 팀 공 사이의 충돌은 기존과 동일하게 계산하지 않습니다.
- 결승선 통과 시점을 보간합니다. 1마이크로초 이내 기록은 공동 순위(예:1,1,3)이며 팀 등록 순서나 충돌 횟수로 우열을 만들지 않습니다.
- 기본 제한시간 90초, 관리자 5~600초. 5초 이상 좁은 범위에 갇힌 공은 정체를 표시하며 같은 물리 규칙을 계속 적용합니다. 마감까지 갇히면 정체 사유로 DNF, 나머지 미도착은 시간 초과 DNF입니다. 미완주에 순위를 부여하거나 강제 완주시키지 않습니다.
- 비활성 탭 등으로 화면 갱신이 멈추면 경기 시뮬레이션도 일시 정지합니다. 경기 시간은 준비 시간을 제외한 실제 시뮬레이션 진행 시간입니다.

## 저장·Slack

IndexedDB의 teams/members/photos/gameSettings에 팀·조원·사진 Blob·설정을 원자적으로 저장합니다. 저장 완료 표시를 확인한 뒤 창을 닫으세요. 결과·경기 상태는 영속화하지 않습니다. 저장이 거부되거나 데이터가 손상되면 안내하며 현재 세션에서 사용할 수 있습니다. 손상된 기존 데이터를 빈 값으로 덮어쓰지 않습니다.

저장된 Slack URL은 해당 브라우저에 접근하는 사용자/코드가 읽을 수 있습니다. 마스킹은 접근 통제가 아닙니다. 경기별 자동 전송 한 번, 실패 후 명시적 재전송만 허용합니다. 읽을 수 있는 성공 HTTP 응답과 'ok' 본문을 확인해야 성공입니다. CORS/네트워크로 성공을 확인할 수 없으면 실패로 표시합니다. 이 경우 수동 재전송은 Slack에 중복 도착할 가능성이 있습니다. 테스트는 Mock만 사용합니다.

## 검증

```powershell
npm run lint
npm run test:unit
npm run build
npm run test:e2e -- --reporter=line
```

단위 테스트는 Node.js 내장 node:test, E2E는 설치된 Microsoft Edge와 Playwright를 사용합니다. E2E는 5188 포트 서버를 실행하거나 재사용합니다. 저장 테스트에는 브라우저 프로필을 닫고 다시 여는 검사, 저장소 차단·손상·스키마·롤백·Blob 정리, Slack opt-in·실패·재전송 검사가 포함됩니다.

경기장/엔진 좌표 및 모델 설명: docs/race-engine-api.md. 요구사항: docs/race-spec.md.

## 한계

임의로 장애물을 겹쳐 배치하면 완주를 보장할 수 없습니다. 팀별 보정 없이 제한시간의 DNF로 처리합니다. 기본 배치는 난이도/복귀 한도/출발 대기 시점/30개 팀 테스트를 통과했습니다. 실제 Slack 운영 Webhook의 외부 전달은 사용자가 실제 설정에서 확인해야 합니다.
